# Vireo: the variant loop as its own product

2026-11-05. Owner: William. Built by the main session. Came from wren `packages/variants`
(wren `designs/2026-11-05-variants.md`, WA-1067.10/.11).

## Goal

Any system can slot in the variant loop. An agent makes a batch, a person marks it
Amazing/Good/Bad with anchored notes, the agent reflects and writes guides, and the market's real
numbers sit beside the taste rank. Wren is the first host. Later it is an upsell: "want to
iterate faster? I slot this into your stack."

## Target shape

Like autobrowse: own repo, public under PolyForm Strict, npm `@wrenautomation/vireo`
(bare `vireo` is taken), bin `vireo`, `v*` tag publishes.

```
@wrenautomation/vireo
  .            vireo(ports) → Vireo: every store call; Collector contract; read-model types
  /schema      drizzle pg tables, schema "vireo"
  /migrations  MIGRATIONS options for the host driver's drizzle migrator
  /stats       Plackett-Luce, Beta posteriors, P(best), Wilson (pure)
  /sync        cut spans <-> footage time (pure, browser safe)
  /media       S3-compatible bucket: put, signed GET
  /cli         registerCommands(cmd, host); bin `vireo` (JSON out, PGlite or DATABASE_URL)
```

One entry: `vireo({db, collectors, hooks})` gives every store call bound to the ports.

The host gives four things. Vireo imports nothing from the host.

| Port | Is | Wren gives |
|---|---|---|
| db | a drizzle pg database | the client's own database |
| collectors | `{channel, target, rates, means?, read(ship)}` per channel | post, site, email collectors (stay in wren) |
| bucket | `Bucket {put, url}`; `s3Bucket(config)` makes one | wren's media bucket |
| hooks | `onWrite(tx, by)` | `setAuditActor` |

The bucket is a CLI-host port only: the store keeps `s3://` uris and a page signs them.
Notify is not a port: a host that wants a ping on a new batch wraps `addBatch`.

Access stays with the host. Vireo takes `by` (who acted) on each write and trusts it.

UI: the host renders vireo's read models (`queue`, `feedback`, `live`). The types are exported, so
a host never copies them by hand. Wren's portal module is the first adapter. A standalone viewer
(`vireo serve`) waits for a host with no UI of its own.

## Decisions

### D1 Packaging: own repo, autobrowse style (William, 11-05)

| | Shape | For | Against |
|---|---|---|---|
| A | Keep in wren, split core and adapters inside | Cheapest | No other repo can use it |
| B | `engine/` package | Public npm, bird family | Engine is the research family; vireo is a product |
| **C** | **Own repo like autobrowse** | Own release, README, license; sells alone | One more repo to keep |
| D | Own service + HTTP API | Fully apart | A second tenancy and a network hop, no gain now |

William chose C: "a core thing that everything might use, and an upsell product".

### D2 Who owns the tables and their migrations

| | How | For | Against |
|---|---|---|---|
| M1 | Host's drizzle-kit reads vireo's schema; host makes migrations | One chain per database | Each host writes its own SQL for vireo; they drift |
| **M2** | **Vireo ships its migrations; host runs `migrate(db)`; host's drizzle-kit skips schema `vireo`** | One SQL for every host; vireo changes ship with vireo | Two migrators per database |
| M3 | Vireo pushes schema at start (drizzle push) | No files | No review of DDL; unsafe on prod |

Chosen M2. Its journal is `drizzle.__vireo_migrations`, beside the host's. A host runs it with its
own driver's drizzle migrator and vireo's `MIGRATIONS` options (no custom migrator).

### D3 Scheduler: Restate only

| | How | For | Against |
|---|---|---|---|
| **S1** | **Restate virtual object `VireoCollect/<key>`, self-scheduling** | Retries, one pass at a time per key, journaled, same controls as every loop | A host needs Restate (wren and autobrowse have it; local is one binary) |
| S2 | cron / host timer | No dependency | No retries, overlapping runs, silent failure |
| S3 | Event: collect after upstream metric pulls | Fresher, fewer passes | Needs the host's loops to call it |

Chosen S1, no cron. William: "why not all just Restate?" Agreed. With no Restate, `vireo collect`
runs one pass by hand (autobrowse tier 0). S3 can come later as a Restate send from wren's metric
loops; it adds to S1.

Wren keeps its own loop wrapper (`makeLoopObject` + ledger) around `collect()`, so its loop
controls stay one shape. A `/restate` object and `vireo worker` for hosts with no loop kit come
with the first such host: no untested loop code before then.

### D4 Stats live in vireo

`fitPlackettLuce`, `tiersToChoices`, `rateSplit`, `posteriors`, `pBest`, `wilson` move to
`/stats`. Wren `@wren/experiments` imports them from vireo: one copy.

### D5 Channels are open

`ships.channel` is any string a collector names. Each collector brings its rates
(`{name, wins, of}`) and its means (metrics averaged, weighted by a count). Derived totals
(post `engaged`) are the collector's rows. Wren registers `post`, `site`, `email`.

### D6 Media is a bucket (William, 11-05)

One S3-compatible client (S3, R2, MinIO): put on add, signed GET on read. No media port.

### D7 Schema name `vireo`

New tables in schema `vireo`. Wren's `variants` schema is dropped after the move. It holds no
rows in wren's database (checked 11-05); each client database is checked before the drop.

## Plan

1. Repo: package, license, README, CLAUDE.md, biome, tsconfig, gates, CI, release.
2. Move code: schema, store, live, stats, sync, collect contract, media, CLI, restate. Errors are
   `VireoError(message, status)`. Tests on PGlite (no Docker).
3. Migrations: vireo's first migration makes schema `vireo`.
4. Publish 0.1.0 (token from the Mac; trusted publishing after).
5. Wren: depend on the exact version; wire db, collectors, bucket, hooks; run vireo's
   `migrate` in wren's migrate step; drizzle-kit drops `variants/src/schema.ts`; portal imports
   vireo types; `wren variants` wraps vireo's command table; `@wren/experiments` imports `/stats`.
6. `packages/variants` shrinks to wren's adapter: collectors, portal service, loop, CLI host.
   Wren's drizzle config keeps the old `variants` tables until William says yes; then one
   migration drops them (empty).
